\chapter{Contexte et Problématique}

\section{Présentation du projet}
AutismCare est une plateforme dédiée à l'accompagnement des enfants atteints de troubles du spectre de l'autisme (TSA). Elle vise à centraliser les outils d'aide à la communication, d'apprentissage, et d'organisation du quotidien.

\section{Problématique}
Comment aider l'enfant autiste à communiquer, apprendre et structurer son quotidien, et offrir aux adultes (parents, éducateurs, spécialistes) un outil unique pour organiser et suivre l'accompagnement ?

\section{Acteurs du système}
\begin{itemize}
    \item \textbf{Enfant} : Utilise l'application pour communiquer (pictogrammes), jouer et suivre son emploi du temps.
    \item \textbf{Parent} : Gère le quotidien, suit les progrès et interagit avec les spécialistes.
    \item \textbf{Éducateur / Spécialiste} : Crée des contenus, gère les disponibilités et les rendez-vous, ajoute des notes de suivi.
    \item \textbf{Administrateur} : Gère la plateforme, les comptes et les ressources globales.
\end{itemize}

% ==========================================
% 2. FONCTIONNALITÉS PRINCIPALES
% ==========================================
\chapter{Fonctionnalités Principales}
La plateforme est divisée en huit grands blocs fonctionnels, correspondant à un microservice ou une brique de la plateforme :

\begin{itemize}
    \item \textbf{Comptes et rôles} : Inscription, connexion (Keycloak), gestion des rôles et droits d'accès.
    \item \textbf{Emploi du temps} : Routine visuelle, rappels, activités faites ou non.
    \item \textbf{Consultations} : Disponibilités des spécialistes, prise de rendez-vous, statuts, notes de suivi.
    \item \textbf{Cours et évaluations} : Cours par catégorie, exercices, résultats, niveau adapté.
    \item \textbf{Jeux éducatifs} : Émotions, mémoire, scores, récompenses symboliques.
    \item \textbf{Communication} : Tableaux de pictogrammes, demandes de l'enfant, historique.
    \item \textbf{Événements} : Ateliers, inscriptions, gestion des places.
    \item \textbf{Ressources} : Fiches, vidéos, recherche par catégorie et niveau.
\end{itemize}

\chapter{Architecture Globale et Choix Techniques}

\section{Vue d'ensemble}
L'architecture repose sur une approche microservices conteneurisés (Docker Compose). Elle est sécurisée par Keycloak (JWT) et utilise une API Gateway pour router les requêtes.

\section{Choix Techniques}
\begin{itemize}
    \item \textbf{Frontend} : Angular
    \item \textbf{API Gateway} : Spring Cloud Gateway (port 8090)
    \item \textbf{Découverte de services} : Eureka Server (port 8761)
    \item \textbf{Sécurité} : Keycloak (port 8180) avec validation des tokens JWT
    \item \textbf{Communication Synchrone} : OpenFeign (entre microservices Spring Boot)
    \item \textbf{Communication Asynchrone} : RabbitMQ (port 5672) pour les événements métier
    \item \textbf{Bases de données} : PostgreSQL et MongoDB (1 base par microservice)
\end{itemize}

\chapter{Contrats d'API et Communications}

\section{Communications Inter-services}
L'architecture utilise deux modes de communication :
\begin{itemize}
    \item \textbf{OpenFeign (Synchrone)} : Par exemple, le service \texttt{course-eval-service} appelle \texttt{resource-service} pour récupérer un média (\texttt{GET /api/resources/\{id\}}).
    \item \textbf{RabbitMQ (Asynchrone)} : Par exemple, le \texttt{consultation-service} publie l'événement \texttt{ConsultationConfirmed}, qui est consommé par le \texttt{schedule-service} pour ajouter automatiquement le RDV au planning.
\end{itemize}
